## 仓库 Repository

仓库就是存放项目的所有源代码文件（还包括一些项目需要的文档和二进制文件）以及我们对它们所做的所有更改的地方。当我们说要应用 Git 源代码控制系统到一个项目时，我们要做的第一件事就是创建一个仓库。

## 初始化 Init

在一个空或非空的目录执行下面的命令来初始化一个仓库，本质上是那个目录建了一个 `.git/` 目录，但这时还未跟踪仓库内的任何文件，只是保持就绪。

```sh
git init
```

## 克隆 Clone

我把服务器（比如 GitHub）的仓库原封不动地复制到我的本地设备上，这叫做克隆。

```sh
git clone https://github/<你的用户名>/<你的仓库>.git
```

## 忽略 Git Ignore

你和同事的开发环境可能不一样，在项目目录中也会有开发环境的特有文件；而你们各自运行或调试项目时，则会产生临时的编译产物。这些文件都不应该被 Git 跟踪，要忽略它们，在项目根目录创建并编辑 `.gitignore` 文件。

在 GitHub 有个包含众多环境下合适的 `.gitignore` 文件的仓库：[github/gitignore: A collection of useful .gitignore templates](https://github.com/github/gitignore "github/gitignore: A collection of useful .gitignore templates")，需要时可直接取用。

## 暂存 Stage

每次提交时，你不是一股脑地把目前的所有更改都提交了，而是有选择地把一些相关联的更改放在一起，组成一个有主旨的提交，这叫暂存。这些暂存的文件所在的地方叫暂存区。

添加一个或多个文件到暂存区：

```sh
git add code1.c code2.c
```

添加指定目录到暂存区，包括子目录：

```sh
git add dir1/
```

添加当前目录下的所有文件到暂存区：

```sh
git add .
```

关于 `git add` 命令，详见 [git add 命令 | 菜鸟教程](https://www.runoob.com/git/git-add.html "git add 命令 | 菜鸟教程")。

Git 还支持比文件更细粒度的暂存，你可以使用 `git add -p` 命令来只暂存一个文件中的某几行改动。具体用法可以问 LLM。

为什么要暂存？暂存可以产生有主旨的提交，这样如果哪些有关联的改动不好，只需要回滚某个提交就行了，不会导致所有更改都回滚了。

## 提交 Commit

提交就是把暂存区的文件附上标题和可选的描述并交给 Git 管理，使用下面的命令做一次提交：

```sh
git commit -m "标题" -m "第一行描述" -m "第二行描述"
```

或者直接执行 `git commit`，在自动打开的文本编辑器（你之前设定的默认文本编辑器）中写入文本，然后保存并退出，注意标题和描述之间要空一行：

```
标题

第一行描述
第二行描述
```

## 修正 Amend

你已经提交了，但是你发现还有一个文件也应该放在这个提交里，或者你上次的提交信息写错了，你可以使用下面的命令修正上一次提交，其本质是用一个新的提交覆盖上次提交：

```sh
git add code3.c
git commit --amend -m "修正后的提交"
```

## 远程 Remote

远程指的就是服务器不与你或你同事的设备就地连接，需要通过远程通信手段连接的状态。远程仓库保存的项目版本通常认为是已经公开确定的，如果你认为你的本地更改已就绪，那么你应该推送一个新的版本到远程仓库，来把你的更改确定下来。

## 本地 Local

你正在使用什么设备写代码，用什么设备通过约定的同步服务器与你同事协作，什么设备就是你的本地设备。你在本地设备上的更改就是本地更改，以此类推。

## 推送 Push

推送就是将本地仓库的提交上传到远程仓库，更新远程分支。

```sh
git push
```

## 拉取 Pull

拉取就是从远程仓库获取所有更新的版本并合并到当前本地分支。由于是获取之后立即合并，相当于 `git fetch` + `git merge`，你没有审查这些更改的机会，你的文件会立即更新。

```sh
git pull
```

## 获取 Fetch

获取就是从远程仓库下载所有更新的版本到本地，但不会自动合并到当前工作分支，仅更新远程跟踪分支（也就是另一个分支）。你可以查看这些最新的更改（”我要验牌“），确认没有问题（”牌没有问题“）之后再执行 `git merge` 合并这些更改。

```sh
git fetch
```

```sh
git merge
```

## 同步 Sync

同步就是一次拉取+一次推送。这组动作是同步自己的本地仓库与远程仓库，于是 Git 把它们合成了一个命令。

```sh
git sync
```

## 贮藏 Stash

你正在处理手头的文件，但是之前的版本突然有一个紧急的 bug 需要修复，你必须贮藏现在的工作，回滚到那个版本把 bug 修复并推送一个修复版本，然后再恢复贮藏的更改。

```sh
git stash
```

## 分支 Branch

分支是一个非常强大的概念。假设随着你的开发，在你的主分支 `main` 上 0.1、0.2 和 0.3 版本陆续上线；现在你要做一个大的功能，它的工时很长，也许一两周甚至一个月，这时你可能需要复制一份 0.3 版本，开启一个新的功能分支 `feature/sth-cool`，然后在这个分支上开发；与此同时主分支也在更新，同事甲修复了一个 bug，推送了 0.3.1 版本；过了一个月，经过数十次提交，你的功能分支开发完毕，是时候把功能分支合并到主分支了；你需要先把 0.3.1 合并到功能分支上的最新提交 ，解决可能的冲突，形成 0.4 版本的提交，然后再把 0.4 推送到主分支。

![Git 分支管理](https://img.xicuodev.top/2026/02/fef7c86de2bd00556e73a626ec40686f.png "Git 分支管理")

如果你要做一个规模很大的尝试，有非常多的文件会受到影响，你也应该创建一个新的分支，经过几次提交之后，你发现这个尝试失败了，你可以直接归档或删除这个分支，而不会影响主分支，你在尝试的过程中也不会影响同事在他们分支的开发。

事实上，当你或你的同事做任何事的时候，都应该创建一个新的分支，有一方开发完成了，就把他分支的最新提交合并回主分支，并解决可能的冲突，这是为了在各自开发时互不影响。当然，实际开发中情况往往更复杂，你可能有开发分支、QA 分支、产品分支等，但是底层是同样的道理。
