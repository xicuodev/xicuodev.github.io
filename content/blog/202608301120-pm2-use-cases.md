用于 Node.JS 的高级生产进程管理器 PM2 是一个守护进程管理器，可以帮助您管理应用程序并使其保持 24/7 全天候在线。

## 注册并启动任务

```sh
pm2 start app.js --name "task_name"
```

## 保存当前进程列表

```sh
pm2 save
```

## 开机自启当前列表

```sh
pm2 startup
```

这会生成全局生效的开机启动脚本，然后复制并执行它输出的那条 sudo 命令。(To setup the Startup Script, copy/paste the following command: ...) 只执行一次，对今后所有任务永久生效。

如果 sudo 环境 PATH 重置导致找不到可执行文件，可使用类似

```
sudo env PATH="/usr/bin:/bin:/usr/sbin:/sbin:$PATH:/opt/homebrew/Cellar/node/26.5.0/bin" /opt/homebrew/lib/node_modules/pm 2/bin/pm 2 startup launchd -u ror --hp /Users/ror
```

的命令（加上系统标准路径 `/usr/bin:/bin:/usr/sbin:/sbin`）。

## 日常维护

- 停止任务：`$ pm2 stop <id|name|...>`
- 移除任务：`$ pm2 delete <id|name|...>`
- 新增或删除任务后，再执行一次 `$ pm2 save`
- 查看列表：`$ pm2 list`
- 重启任务：`$ pm2 restart <task-name> --update-env`
- 移除初始化脚本: `$ pm2 unstartup launchd`

## Windows 平台

```sh
npm install -g pm2-windows-startup
pm2-startup install
pm2 save
```

## 由 DSH 3080 端口被占用引出的 pm2 进程管理问题

用 pm2 托管 dsh web 之后，`pm2 restart dsh` 经常起不来，日志里刷的全是这个：

```
Error: listen EADDRINUSE: address already in use 127.0.0.1:3080
```

3080 上那个进程不是 pm2 拉起来的。`pm2 restart` 只杀自己 fork 出来的进程，手里没有它的 pid，所以怎么重启都碰不到它，只能每隔几秒崩一次，然后无限重启下去。

```
$ lsof -nP -iTCP:3080 -sTCP:LISTEN
COMMAND     PID USER   FD   TYPE             DEVICE SIZE/OFF NODE NAME
node      81011  ror   14u  IPv4 0x81392fdcfeda9da9      0t0  TCP localhost:stm_pproc (LISTEN)
```

`stm_pproc` 是 macOS 给 3080 起的名。81011 不在 pm2 的进程树里，`pm2 list` 列不出它，GUI 却一直是它在响应。

源头在 dshmarket，也就是 DSH 的插件市场。装插件、更新插件这类操作它可能会引导你点它的一键重启，这走的是 `restart.js` 的 `scheduleRestart()`：

```js
const helper = spawn(nodeExecutable(), ['-e', restartHelperSource(...)], {
    detached: true, stdio: 'ignore', env: process.env,
});
helper.unref();
setTimeout(() => process.kill(process.pid, 'SIGTERM'), 500);
```

helper是`detached`和`unref`的。它等端口释放，再生成（spawn）一个全新的`dsh web`，命令行参数从`process.argv`原样重放，500ms后给原来的进程发SIGTERM让它自我了断。新进程的父级是helper，helper一退就归launchd，不在pm2树里。然而，detached self-restart在systemd、launchd、pm2下都不安全。

决定走不走这条路(`detached`+`unref`)的是`restartAllowed()`，它只认systemd，不认pm2和launchd：

```js
if (config.allowRestart !== undefined) return config.allowRestart;
return detectedSupervisor(env, ppid) === null;
```

pm2日志里能清楚地区分是市场自己退的还是pm2退的。市场退时的两行：

```
2026-09-24T04:32:00: App [dsh:3] exited with code [0] via signal [SIGINT]
2026-09-24T04:32:03: App [dsh:3] exited with code [1] via signal [SIGINT]
```

对照pm2退时的三行：

```
2026-09-24T11:00:39: PM2 log: Stopping app:dsh id:3
2026-09-24T11:00:39: PM2 log: pid=53745 msg=failed to kill - retrying in 100ms
2026-09-24T11:00:40: PM2 log: App [dsh:3] exited with code [130] via signal [SIGINT]
```

第一行前面没有 `Stopping app:dsh`，且退出码不一样，因为 DSH 的启动器给两个信号装了不同的处理：市场发的 SIGTERM 走 0，pm2 停进程发的 SIGINT 走 130。

答案呼之欲出，关掉市场的重启，以后都通过pm2重启即可。在`~/.dsh/profiles/web/cordis.patch.yml`顶层加两行：

```yaml
- id: dsh-market
  config:
    allowRestart: false
```

关掉之后插件改动要自己 `pm2 restart dsh` 重启 dsh web 生效。

```
pm2 stop dsh
lsof -nP -iTCP:3080 -sTCP:LISTEN
kill <pid>
pm2 start dsh
```
